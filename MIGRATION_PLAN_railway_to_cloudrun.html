백엔드 이전 계획: Railway → Google Cloud Run

작성일 2026-07-13 · 목적: Railway 무료기간 종료로 백엔드 중단(조회·메일 전면 불가) 복구. 확정 사항 = 프로그램 재개발 아님, 호스팅만 이전. 호스팅 = Google Cloud Run (Render 유료안은 검토 후 제외).

한 줄 요약: 프로그램 코드·프론트엔드는 그대로 두고 실행 위치만 Railway → Cloud Run(도쿄)으로 옮긴다. /data 는 GCS 버킷을 마운트해 코드 수정 0줄로 유지한다. 마지막에 Vercel 환경변수 한 줄만 새 주소로 교체한다.

0. 현재 상태 (진단 완료)

  • Railway 서비스 Redelivery = Failed (삭제 아님, 무료 크레딧 소진 추정).
  • 도메인 redelivery-production.up.railway.app → "Application not found" 404 → 실행 중 앱 없음.
  • Vercel 프론트가 이 죽은 주소로 /query·/email-templates 호출 → 조회·메일 동시 실패.
  • Railway 볼륨(49MB)에 credentials.json + 세션파일 존재 가능성.

1. 왜 Cloud Run (Render 대비 결정 근거)

Cloud Run ✅ 선택Render 유료 (제외)
비용사용량 기반, idle 시 $0 → 거의 무료$7/월 고정
속도idle 후 첫 요청 콜드스타트(감수)항상 warm
결정사내 저사용 도구 → 무료 이점 큼—

콜드스타트가 업무에 걸리면 min-instances=1로 전환해 항상 warm(월 소액) 하게 조정 가능.

2. 그대로 유지되는 것 변경 없음

  • 프론트엔드(Next.js/Vercel) — 코드·배포 그대로.
  • 스크래퍼 로직 전체 (TEXA·TRIT·GOLD·FLOR·GESE·이메일 템플릿).
  • scraper/Dockerfile — PORT 존중 + chromium 설치 포함 → Cloud Run 즉시 호환.
  • 백엔드 파일 경로 /data — 그대로 (3번에서 버킷을 이 경로에 마운트).
  • CORS allow_origins=["*"] — 그대로 동작.

3. 핵심 관건: /data 영속화 작업 필요

Cloud Run 컨테이너는 재시작 시 로컬 디스크가 날아간다. /data 내용:

  • credentials.json — 전 임대사·선사 로그인 정보. 반드시 보존.
  • flor_session_*.json, texa_session_*.json — 세션 캐시. 없으면 자동 재로그인 → 보존 불필요(재생성).
해법: GCS 버킷을 /data 에 마운트. 코드는 여전히 /data/credentials.json 을 읽고 쓰지만 실제 저장은 버킷에 영구 보관 → 코드 수정 0줄, 재시작에도 데이터 유지.

4. 기존 credentials.json 결정 필요

방안내용비고
A. 재입력 (권장)가동 후 화면에서 임대사 로그인 정보 다시 입력Railway 안 건드림, 가장 깔끔
B. Railway 회수Railway 잠시 살려 credentials.json 다운→버킷 업로드기존 보존, Railway 소액 요금

5. Cloud Run 배포 설정

설정값

max-instances상한 설정 + 예산 알림 (요금 폭증 방어)

6. 작업 순서 (단계별 승인)

  1. gcloud CLI 설치 (Windows) → gcloud init 로그인.
  2. GCP 프로젝트 생성 + 결제 연결 (콘솔). API 활성화: Cloud Run, Cloud Build, Cloud Storage.
  3. GCS 버킷 생성 (도쿄) — /data 용.
  4. [4번 결정] credentials 재입력(A) / 회수(B).
  5. Cloud Run 배포 — gcloud run deploy (소스 scraper/) + 5번 설정 + 버킷 마운트.
  6. 배포 검증 — *.run.app/ 헬스체크 200 + 테스트 조회 1건.
  7. Vercel 환경변수 교체 — RAILWAY_API_URL → 새 주소. 재배포.
  8. 운영 확인 — redelivery-pi.vercel.app 조회·메일 정상.
  9. 정리 — Railway 서비스 삭제(선택), 문서 갱신.

7. 롤백

Vercel 환경변수만 되돌리면 즉시 이전 상태로. 코드 변경 없음 → 리스크 낮음.

지금 필요한 것: (1) Google Cloud 계정+결제 준비, (2) 4번 credentials A/B 결정. 각 단계는 성현님 계정 작업(gcloud 로그인·결제·콘솔)이 포함되므로 단계마다 함께 진행합니다.
