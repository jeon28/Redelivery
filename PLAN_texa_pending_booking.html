TEXA — Pending Booking 컨테이너 조회 수정 계획

대상 임대사: TEXA (Textainer) · 사례: 장금상선 / 인천 / TEMU4164610

1. 목표

이미 Pending Booking 에 배정된(=예약 완료) 컨테이너를 조회 시 가능으로 표시하고 반납번호·반납지·유효기간을 채운다. 현재는 상황에 따라 "정보 없음" 또는 "불가" 로 잘못 뜬다.

2. 현상 (재현된 실제 로그)

단계사이트 상태현재 결과
1차 조회 can be booked → 자동 Book 실행 → 예약 TKG6G40 실제 생성됨 "임대사 시스템에 해당 컨테이너 정보 없음"
2차 조회(재전송) cannot be redelivered → ASSIGNED TO PENDING BOOKING - TKG6G40 / INC / 2S / SINOK1 / 2026-JUL-23 "불가"

3. 원인 분석

버그 A — 자동 Book 성공 감지 실패. Book 직후 성공 정규식 New Booking - X is created successfully 가 안 맞고, 이어지는 재-Preview 는 방금 만든 예약 때문에 are booked 가 아니라 cannot be redelivered / ASSIGNED TO PENDING BOOKING 로 바뀐다. 그런데 _reopen_and_parse_booked() 는 "are booked" 만 성공으로 인정 → 성공한 예약이 실패로 처리되어 "정보 없음" 마감.
버그 B — Pending Booking 이 무조건 불가. cannot be redelivered 표의 모든 행을 그대로 reason 만 채우고 available=False 유지. ASSIGNED TO PENDING BOOKING 사유 문자열에는 이미 반납번호·도시·계정·만료일이 들어있는데 이를 파싱하지 않고 불가로 처리.

4. 수정안

파일: scraper/scrapers/texa.py

  1. 신규 헬퍼 _apply_pending_booking(row, reason) -> bool
    ASSIGNED TO PENDING BOOKING - {ref} / {city} / {spec} / {account} / {expiry} 매칭 시 / 로 분해 → booking_ref=ref, depot=city, close_date=expiry(유효기간), available=True, reason=None 세팅 후 True 반환. 아니면 False.
    유효기간에는 만료일(expiry)만 매핑 (신청일 매핑 금지 — 기존 규칙 준수).
  2. Case 1 (cannot be redelivered) 표 파싱을 _parse_cannot_table(frame, results) -> bool 로 추출하고, 각 행에서 먼저 _apply_pending_booking 시도 → 실패 시에만 기존처럼 reason 세팅.
  3. 버그 A 수정: _reopen_and_parse_booked() 에서 재-Preview 결과가 are booked 가 아니고 cannot be redelivered 면 _parse_cannot_table 을 호출. Pending Booking 이 하나라도 매칭되면 True(성공) 반환 → "정보 없음" 오분류 제거.
  4. (부가) Book 성공 로그 정규식에 pending 케이스 문구도 추가해 진단 정확도 향상 (동작에는 영향 없음).

5. 작업 순서

  1. 헬퍼 2개 추가 + Case 1 로직 교체 (texa.py)
  2. 로컬 문법/임포트 확인
  3. 커밋 → Cloud Run 수동 배포 (gcloud run deploy --source scraper)
  4. TEMU4164610 재조회로 가능 + TKG6G40 + 2026-JUL-23 확인

6. 리스크 / 검증

  • 이 컨은 이미 예약(TKG6G40)이 생성된 상태라 재조회해도 중복 예약이 발생하지 않음 (cannot-redeliver 경로 → Book 미실행).
  • 사유 문자열 포맷이 다른 케이스가 있을 수 있어 / 분해를 방어적으로(개수 가변) 처리.
  • 다른 cannot-redeliver 사유(예: 실제 반납 불가)는 기존대로 불가 유지 — pending 문구만 선별 처리.
