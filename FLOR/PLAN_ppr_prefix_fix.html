FLOR 반납번호(PPR) 누락 수정 계획

2026-10-16 · 대상: scraper/scrapers/flor.py

1. 증상

FLOR 반납 생성 요청 후 결과 표에 ✅ 가능으로 표시되지만 반납번호 칸이 비어 있음(-). Florens 사이트에는 실제로 생성되어 있음 (번호 형식 PPT12345 유사).

2. 원인

반납번호 인식 정규식이 PP[RF]\d+ — 즉 PPR / PPF 접두어만 인식. Florens가 PPT… 등 다른 접두어로 발급하면 번호를 못 찾아 booking_ref 가 비게 됨.

위치역할영향
flor.py:863, 898, 921Confirm 후 신규 번호 추출·매핑신규 발급 번호 누락 (이번 증상)
flor.py:983Step3 "Redelivery number:" (precleared) 감지이미 발급된 건 판별 실패 → 중복 발급 위험
flor.py:1140Step3 거부 사유 내 기존 번호 감지동일
flor.py:1491Status 탭 행 파싱재조회 시에도 기존 번호를 못 읽음

3. 수정 내용

  1. 번호 패턴 일원화: 모듈 상수 PPR_RE = r"PP[A-Z]\d+" 하나로 정의하고 위 5곳(JS 문자열 포함)을 모두 이 패턴으로 교체. PPR/PPF/PPT 및 향후 다른 접두어도 인식.
  2. Status 탭 보강 조회(안전장치): Confirm 후에도 번호를 못 찾은 컨테이너만 Status 탭으로 이동해 _search_one 으로 재조회 → Open 행의 번호를 채움. Confirm 화면 구조가 바뀌어도 번호를 확보.
  3. 그래도 못 찾으면 조회 결과 칸에 "발급됨 — 반납번호 확인 필요 (Florens Status 탭 확인)" 문구 표시 (지금처럼 조용히 빈칸으로 두지 않음).

4. 영향 범위 / 비변경

  • 수정 파일: scraper/scrapers/flor.py 1개. 프론트엔드 변경 없음.
  • 기존 PPR/PPF 번호 동작은 그대로 유지.
  • Confirm 클릭 횟수·조건은 변경 없음 (중복 발급 위험 증가 없음, 오히려 precleared 감지가 개선되어 감소).
  • 보강 조회는 번호 누락 시에만 실행 → 정상 케이스 소요시간 변화 없음.

5. 작업 순서

  1. PPR_RE 상수 추가 및 5곳 교체
  2. query() Phase B 이후 누락분 Status 재조회 로직 추가
  3. 로컬 단위 확인 (정규식 / 판정 함수) — 실 발급 테스트는 하지 않음
  4. 배포 후 실제 1건 반납 생성으로 반납번호 표시 확인 (사용자 확인)
