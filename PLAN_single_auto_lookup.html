단건 통합조회 — 컨테이너 번호만으로 임대사·반납지역 자동 지정

작성일: 2026-10-26 · 상태: 검토 대기 · 관련: docs/PLAN_UNIFIED_QUERY_AND_EMAIL.md(기존 통합 화면)

1. 목표

  • 선사 선택 + 컨테이너 번호 1개 입력만 하면 임대사·반납지역·타입이 자동으로 채워진다.
  • 판별된 임대사가 홈페이지 조회형이면 [🔍 조회], 메일형이면 [📧 메일 보내기]가 바로 뜬다.
  • 이 화면을 로그인 후 첫 화면으로 한다. 여러 개 조회는 지금 화면을 [다중 조회] 메뉴로 옮겨 그대로 쓴다.
  • 한 번에 1개만 조회해서 응답이 오래 걸리지 않게 한다.

2. 합의된 결정 사항

#항목결정
1임대사 판별리스 장비 목록(업로드) 우선 → 없으면 접두어 표
2반납지역로그인 사무소 기준 자동(인천→인천, 본사→인천). 화면에서 변경 가능
3메뉴[통합 조회] [다중 조회] [임대사 판별] [Email Setting] [비밀번호 관리]. 첫 화면 = 통합 조회
4타입메일형일 때만 타입 선택칸 표시. 목록에 타입이 있으면 자동, 없으면 기본 45GP
5입력 개수통합 조회는 1개 고정. 여러 개는 다중 조회 화면
6판별 원본월별 반납 대장 엑셀(장금흥아26반납밴10월.xlsx)을 그대로 업로드. 월별 시트를 자동으로 인식
7임대사 별칭MWSL = MWSC (CALT도 MWSC+CALT 묶음), TEXT = TEXA 오타, GLOD ↔ GOLD (선사별 표기)
8미등록 임대사HSLN, BEST, KYSP는 판별 결과만 보여 주고 "시스템 미지원 임대사"로 안내. 버튼 없음
9겹치는 접두어BMOU/BEAU→BCON, DFSU/FDCU→FLOR, HALU→MWSC, KMLU→HSLN을 기본값으로. 대장에 있는 번호는 대장 값 우선
10하위 코드TRIT+TRAM, FLOR+DFIC, GESE+CROS/SGCN은 묶음 단위로 판별
11FLOR 반납CY마지막 선택을 기본값으로. 처음이면 선택 버튼이 빨간색으로 표시됨(다중 화면과 동일)

동작 규칙

  • 번호 11자리가 입력되면 ISO 6346 체크디짓을 확인한다. 틀리면 빨간 경고("번호 오타 의심")를 띄우되 진행은 막지 않는다.
  • 판별 결과는 세 가지로 표시한다. 목록 일치, 접두어 판별, 미판별. 미판별이면 임대사 드롭다운을 직접 고른다.
  • 판별된 임대사가 고른 선사의 임대사가 아니면(예: 흥아 + CAIC) 경고를 띄우고 버튼을 잠근다. "선사를 확인하세요"로 안내한다.
  • 접두어 하나가 여러 임대사에 걸리면 후보를 버튼으로 보여 주고 고르게 한다.
  • [변경]으로 자동 판별을 언제든 직접 덮어쓸 수 있다.
주의: 조회형 임대사 중 FLOR, TEXA, GOLD 등은 조회 = 실제 반납번호 발급입니다. 기존 동작과 같습니다. 단건 화면은 입력이 쉬운 만큼, 버튼 아래에 "조회 시 실제 반납 신청이 진행됩니다" 문구를 상시 표시합니다.

4. 임대사 판별 데이터

4.1 리스 장비 목록 (1순위)

  • [임대사 판별] 메뉴에서 반납 대장 엑셀을 그대로 업로드한다. 양 선사가 한 파일에 있으므로 한 번에 올리고, 올릴 때마다 통째로 교체한다.
  • 머리행에 Container No와 Lessor가 있는 시트만 읽는다(월별 시트 23개, 컨테이너 1,590개 확인). 범례, DOL초과 같은 시트는 건너뛴다.
  • 사용하는 열: Container No, Lessor, LINE(SKR/HAS → 선사 확인 경고), TPSZ(타입 자동). 같은 번호가 여러 행에 있으면 조회일(첫 열)이 가장 최근인 행을 쓴다.
  • 저장 위치는 /data/lease_inventory.json이다. GCS 마운트라 재배포해도 유지된다.

4.2 접두어 표 (2순위)

  • 4자리 접두어 → 임대사 코드 표. [임대사 판별] 메뉴에서 행을 추가·수정·삭제할 수 있다. 저장 위치는 /data/prefix_map.json이다.
  • 기본값: 반납 대장에서 집계한 표(2026-10-26 검수 완료)를 코드에 넣는다.

메서드경로설명

GET/PUT/prefix-map접두어 표 조회·저장
POST/lease-inventory반납 대장 엑셀 업로드 → 파싱 → 교체 저장. 건수, 읽은 시트, 미등록 임대사명을 돌려준다

조회와 메일 발송은 기존 /query, 템플릿, mailto 로직을 그대로 재사용한다. 신규 스크래핑 로직은 없다.

7. 작업 순서

  1. 이 계획서 승인 + 리스 목록 샘플 파일 수령
  2. 백엔드: 판별 로직·체크디짓·API (+ 단위 테스트)
  3. 접두어 초안 수집(로그 + 샘플) → 부장님 검수
  4. 프론트: 공통 로직 분리 → 다중 조회 화면이 그대로 동작하는지 확인
  5. 프론트: 통합 조회 화면 + 임대사 판별 설정 화면 + 메뉴
  6. 로컬 확인 (조회형·메일형·미판별·선사 불일치·체크디짓 오류 케이스)
  7. 커밋 → Cloud Run 배포(승인 후) + Vercel 배포
